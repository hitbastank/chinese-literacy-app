# 文档驱动开发流程

每次开始新的开发任务时，必须遵循以下流程：

## 1. 阅读核心文档

在开始任何开发工作之前，先阅读以下文档了解项目背景：

- **PROJECT_BIBLE.md** - 项目主文档，包含产品愿景、功能规划、设计规范、技术架构
- **RELEASE_NOTES.md** - 发布日志，了解最近的更新

## 2. 确认需求与文档一致性

- 检查用户需求是否在 PROJECT_BIBLE.md 的路线图中
- 如果是新需求，需要先更新 PROJECT_BIBLE.md 再开始开发

## 3. 开发过程

- 参考 PROJECT_BIBLE.md 中的设计规范进行开发
- 保持代码风格与现有代码一致
- 使用 Minecraft 主题的造句和示例

## 4. 完成后更新文档

开发完成后，必须更新以下文档：

### 更新 RELEASE_NOTES.md

在文件顶部添加新的版本记录，格式如下：

```markdown
## YYYY-MM-DD

### 🎯 新功能
- 功能描述

### 🐛 问题修复
- 修复描述

### 🛠 系统优化
- 优化描述
```

### 更新 PROJECT_BIBLE.md（如适用）

- 如果完成了路线图中的任务，将状态从 `[ ]` 改为 `[x]`
- 如果添加了新功能，更新"已完成功能"列表
- 如果有设计变更，更新设计规范部分

## 5. 提交说明

确保用户了解：
- 本次更新了哪些内容
- 文档的哪些部分被更新了
- 下一步建议做什么
